================================================================================
NETWORK SIMULATION (OMNeT++ - IEEE 802.11p)
================================================================================
La rete è simulata FISICAMENTE da OMNeT++ usando il framework INET.
NON ci sono "fasi" predefinite - il comportamento dipende dalla fisica reale.

COME FUNZIONA IL PACKET LOSS:
  Il packet loss è determinato da:
  - Distanza tra veicoli (path loss)
  - Potenza trasmissione: 20mW
  - Sensibilità ricevitore: -85dBm
  - Interferenze radio tra veicoli
  - Rumore di fondo: -110dBm

RANGE APPROSSIMATIVO (line-of-sight):
  - Distanza < 300m:  Ottima comunicazione (0-1% packet loss)
  - Distanza 300-400m: Buona comunicazione (5-15% packet loss)
  - Distanza 400-500m: Comunicazione degradata (30-60% packet loss)
  - Distanza > 500m:  Quasi nessuna comunicazione (>90% packet loss)

DELAY DI RETE:
  Il delay è calcolato da OMNeT++ basandosi su:
  - Tempo di propagazione fisica (~3.3 μs/km)
  - Processing time (codifica/decodifica)
  - Contention (CSMA/CA wait)
  Tipicamente: 1-50ms per distanze < 500m

COME PYTHON RILEVA LE PERDITE:
  - OMNeT++ invia ACK solo per pacchetti arrivati
  - Python rileva gap nei sequence numbers (es. riceve #1, poi #4 → #2 e #3 persi)
  - Applica le perdite ai frame successivi (lag di 1-2 frame)

NOTA: Il comportamento della rete cambia DINAMICAMENTE durante la simulazione
      in base al movimento dei veicoli nella scena.

Per disabilitare completamente OMNeT++ usare: --network_disable

cmd 4 (Monitor CPU Konro) - avviare dopo cmd 3, sostituire XXXXX col PID che appare nel log Konro:
  # Il PID appare nel log di Konro nella riga:
  # "WORKLOADMANAGER FeedbackRequest received {"name":"test_codet_network.py","process_pid":XXXXX,...}"

PID=XXXXX
watch -n 1 "
echo '=== Core assegnati (indici CPU) ===' 
sudo cat /sys/fs/cgroup/konro.slice/app-${PID}.scope/cpuset.cpus
echo ''
echo '=== Core effettivamente attivi ==='
sudo cat /sys/fs/cgroup/konro.slice/app-${PID}.scope/cpuset.cpus.effective
echo ''
echo '=== CPU load per core (PUs) ==='
sudo grep 'PUs' /proc/1/fd/1 2>/dev/null | tail -1
"

  # Nota: con CoperceptionPolicy, feedback < 90 aggiunge core, feedback > 110 ne rimuove.
  # Dopo 5 cicli consecutivi con feedback < 90, Konro conclude che il bottleneck
  # e' il canale radio (non la CPU) e torna a 1 core.
