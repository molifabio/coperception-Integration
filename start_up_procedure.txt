uso cmd 3x con storico JSON (importante)

  - --summary_out ora va trattato come file storico: ogni run viene aggiunta (append) in runs[]
  - stesso file + scene_id diversi = storico multi-run/multi-scena
  - una run e' considerata completata quando il test finisce senza errori (run_completed_scene=true nel JSON)

esempio: eseguire 3 scene nella stessa condizione (konro+omnet)

for SCENE in 29 30 31; do conda activate coperception && cd ~/coperception/coperception-Integration/tools/det && python test_codet_network.py --com disco --data ~/coperception/coperception-Integration/data/V2X-Sim/V2X-Sim-det/test --resume ~/coperception/coperception-Integration/data/V2X-Sim/V2X-Sim-2.0/checkpoints/det/disco/no_rsu/epoch_100.pth --logpath ~/coperception/coperception-Integration/logs --network_host 127.0.0.1 --network_port 5555 --konro_enable --konro_target 0.85 --konro_interval 1 --konro_agent_id 1 --network_profile good:30:0.02:0.00,down:30:0.40:0.15,recover:40:0.08:0.02 --network_profile_seed 123 --summary_out ~/coperception/coperception-Integration/logs/ab/with_konro_with_omnet_history.json --scene_id ${SCENE}; done

cmd 4 (Monitor CPU Konro) - avviare dopo cmd 3, sostituire XXXXX col PID che appare nel log Konro:
  # Il PID appare nel log di Konro nella riga:
  # "WORKLOADMANAGER FeedbackRequest received {"name":"test_codet_network.py","process_pid":XXXXX,...}"

PID=XXXXX
watch -n 1 "
echo '=== Core assegnati (indici CPU) ===' 
sudo cat /sys/fs/cgroup/konro.slice/app-${PID}.scope/cpuset.cpus
echo ''
echo '=== Core effettivamente attivi ==='
sudo cat /sys/fs/cgroup/konro.slice/app-${PID}.scope/cpuset.cpus.effective
echo ''
echo '=== CPU load per core (PUs) ==='
sudo grep 'PUs' /proc/1/fd/1 2>/dev/null | tail -1
"

  # Nota: con CoperceptionPolicy, feedback < 90 aggiunge core, feedback > 110 ne rimuove.
  # Dopo 5 cicli consecutivi con feedback < 90, Konro conclude che il bottleneck
  # e' il canale radio (non la CPU) e torna a 1 core.
